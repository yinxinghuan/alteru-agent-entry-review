# AlterU U Agent 角色系统

> 状态：平台吉祥物候选，尚未完成正式命名与品牌定版。  
> 当前原型：评审页中的“方案二 · U 字母角色 / U-born Agent”。  
> 最近确认：2026-08-15。

## 1. 角色定位

这个小角色不是一个把 AlterU Logo 贴在身上的独立机器人，而是由平台游戏水印的 `U` 本身长成的 Agent。它首先是稳定的平台入口，其次才在需要沟通时短暂获得脸、双手和说话能力。

当前职责只承担左上角 Agent 入口的两类沟通：

- 没有待办时，主动邀请用户创建游戏。
- 有待回复消息时，提示“轮到你了”并进入对应会话。

当前产品合同明确不支持第三种“多条待办”视觉状态、数量徽标或队列展开。即使后台存在多条消息，入口也只接收一个当前需要用户进入的对应会话。

它有潜力发展成 AlterU 的平台吉祥物，未来可以进入新手引导、Agent 工作状态、通知、空状态、加载与完成反馈、活动页和游戏内平台层，但正式扩展前仍需补齐命名、性格、语气与品牌使用规范。

## 2. 不可丢失的识别锚点

1. **正式 U 水印就是身体。** 使用游戏里确认过的 U / Alpha 图形，不使用完整 `AlterU` 字标，也不把 U 当作贴在机器人胸口的 Logo。
2. **U 始终存在。** 角色出现或收回时，U 可以有一次轻微弹性反应，但不能消失、换形或被其他身体遮住。
3. **脸从 U 内部生长。** 当前脸位于 U 的内弯下部，用粉色软体形状承载双眼；它应读成“U 活过来了”，不是另一个角色站到 U 前面。
4. **手臂只有 0 或 2 两种数量。** 不允许只显示一只手。需要表达时两只同步出现，动作结束后两只同步收回。
5. **双手可以不对称表演。** 左手负责稳定轮廓或支撑，右手负责挥手、指向；多待办时可以双手向外打开。数量对称，动作职责不必镜像。
6. **静止时保持克制。** U 在等待期间不持续晃动；弹性只服务于脸和双手伸出、收回的瞬间。
7. **原生端使用自洽的 Lottie 图层。** 正式 U 是两个纯矢量 Shape Path，不使用内嵌 PNG；双眼是位于粉色脸上方的两个独立 Shape Layer；画布自带平台黑色背景，保证白色 U 在 LottieFiles 等白色预览环境中仍然可见。MiniAPP 继续使用正式 SVG 路径。
8. **MiniAPP 与线上组件同源。** `https://yinxinghuan.github.io/alteru-agent-entry-review/?v=ab3ea266` 中的角色与气泡组件是 MiniAPP 的唯一视觉基准；导出 SVG 直接复用其 `42 × 44px` 角色、`9px` 间距、脸/双眼/双手和尾尖几何，不再另画近似版。

## 3. 气泡几何合同

- 基础高度固定为 `36px`，四角统一使用 `18px` 圆角。
- 展开气泡采用固定左右内边距 `14px`，宽度由内容动态决定；手机可缩至 `12px`。
- 气泡尾巴固定在靠近角色的一侧，不能因文字长度改变位置或姿势。
- MiniAPP / Web 的气泡尾巴固定为 `11 × 11px`，位于主体左侧 `-6px`、底部 `5px`，旋转 `8deg`，与主体保持足够重叠；原生 Lottie 因渲染器抗锯齿差异，使用同填充 Shape Layer 内的兼容路径消除接缝。
- 思考阶段必须是 `36 × 36px` 的正圆空白气泡，内部有 3 个居中圆点。
- 文案阶段从思考圆平滑展开为动态长度，不能为每句文字单独手调宽度、圆角或边距。
- 当前主色：白色用于普通邀请，品牌粉用于需要用户行动的提醒；状态不能只依靠颜色表达。

## 4. 当前动作语法

### 空闲招呼

`纯 U → U 轻弹 → 脸长出 → 36px 思考圆 / 三个点 → 双手出现并展开 Create a game? → 气泡收回 → 双手与脸收回 → 纯 U`

- 当前评审循环用于展示完整过程；产品空闲邀请单次动画为 7 秒，其中 `Create a game?` 完全显现后保持约 3 秒。
- 产品定版节奏：页面稳定后随机等待 5–10 秒首次出现；之后每次播放完成后重新随机等待 10–30 秒，只要仍为空闲状态就持续循环，不设置播放次数上限。
- 用户最近 8 秒内有点击、触摸、键盘或滚动操作时顺延；页面不可见时暂停计时。有待回复状态时完全禁止空闲邀请。
- 气泡和角色都必须完成收回，不能停在打招呼状态。

### 等待回复

- 待回复事件立即中断空闲动画。
- U 保持在原位，脸出现；两只手短暂出现，右手指向信息、左手支撑轮廓。
- 完整文案：`Your turn — I’m waiting`。
- 当前交付动画为 4 秒，之后收为安静的常驻状态；完成回复或任务取消后清除。
- 点击必须进入业务层传入的对应会话，不由动效组件自行选择或排序会话。

### 减少动态效果

- `prefers-reduced-motion` 下不依靠动作传达唯一信息。
- 当前角色保持可识别的 U 与可读文案，手臂默认不出现，避免静态画面产生不完整姿势。

## 5. 语气与文案原则

- 先说明用户能做什么或现在需要做什么，不写只有情绪、没有行动含义的卖萌台词。
- 文案短、直接、像一个主动但不催促的协作伙伴。
- 空闲邀请使用动作动词：`Create a game?`。
- 待回复使用轮次语言：`Your turn`、`I’m waiting`。
- 吉祥物化之后可以增加性格，但不能牺牲 Agent 入口的功能清晰度。

## 6. 可扩展场景

优先级从高到低：

1. 平台左上角 Agent 入口与待回复通知。
2. 创建游戏流程中的引导、思考、生成、完成与失败恢复。
3. 平台空状态、首次使用提示和轻量帮助。
4. 活动页、更新提示和平台级成就反馈。
5. 游戏内的平台层提示，但不能覆盖或取代各游戏自己的主角与美术风格。
6. 贴纸、短视频、社交媒体和周边；需要先完成正式角色设定与品牌审批。

扩展时应优先增加表情、姿势和状态，而不是为每个场景重新设计身体。若未来探索腿、全身比例或更大尺寸插画，必须保留“U 是身体”的核心结构，并与当前 40–42px 小尺寸版本建立明确的同一角色关系。

## 7. 禁止方向

- 不使用完整 `AlterU` 字标替代 U 水印。
- 不把 U 做成机器人胸牌、屏幕贴纸或随时可以移除的配件。
- 不让 U 在角色出现前消失，再由机器人重新带回来。
- 不出现单只手、散落肢体或难以看出整体动作的姿势。
- 不让双手、脸或气泡永久高频晃动。
- 不为不同文案手调不一致的气泡圆角和内边距。
- 不用 Emoji 代替角色状态或功能图标。
- 不让平台吉祥物在游戏内部抢过游戏主角的视觉中心。

## 8. 后续待定

- 正式名称：`U-born Agent` 目前只是评审工作名。
- 角色性格、第一人称语气、是否有固定口头禅。
- 正式颜色、反白版、浅色背景版和极小尺寸版本。
- 大尺寸全身造型是否需要腿，以及手脚的正式比例。
- 它与多个不同 Agent 身份之间的关系：平台统一助手、Agent 容器，还是独立角色。
- 表情库、动作库、声音标识与无障碍替代方案。
- 是否进入正式品牌手册，以及组件与素材的唯一分发位置。
